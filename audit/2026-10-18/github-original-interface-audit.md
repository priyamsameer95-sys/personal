## THEYA.Audio

**Strongest original interface:** `theya/original/static/index.html`, a complete 2-Voice RAG Studio, rather than an API-only project. It contains a source/document entry area, sentence-aware A/B reading view, voice/sound controls, a three-lens distillation area and RAG query/evaluation controls. Lead with a screenshot of this actual interface.

**Isolated render:** `theya/preview/index.html`. Original markup/style/interaction code is retained. Remote fonts and Tesseract are removed, all service connections blocked by CSP, and the extraction call returns labelled synthetic dialogue input. Automatic distillation is disabled; no inference or audio was generated. Caption: “Original THEYA.Audio frontend — synthetic preview text; service connections disabled.”

**Actual implementation evidence:**

- FastAPI/Pydantic extraction routes and streaming audio responses: [app/main.py:133](https://github.com/priyamsameer95-sys/THEYA.AUDIO/blob/8369cfc5b641b5c3eb270eea9651a56d02bbc0de/app/main.py#L133), [app/main.py:564](https://github.com/priyamsameer95-sys/THEYA.AUDIO/blob/8369cfc5b641b5c3eb270eea9651a56d02bbc0de/app/main.py#L564).
- Extraction uses trafilatura plus a Jina fallback; sentence segmentation uses pysbd. These are extraction/segmentation tools, not LLMs. [requirements.txt](https://github.com/priyamsameer95-sys/THEYA.AUDIO/blob/8369cfc5b641b5c3eb270eea9651a56d02bbc0de/requirements.txt#L1), [app/extract/pipeline.py](https://github.com/priyamsameer95-sys/THEYA.AUDIO/blob/8369cfc5b641b5c3eb270eea9651a56d02bbc0de/app/extract/pipeline.py#L1).
- TTS routing selects Microsoft Edge neural synthesis or Kokoro-82M. Kokoro integration uses Hugging Face InferenceClient with `hexgrad/Kokoro-82M` and the fal-ai provider; it is not proof that every provider/model has been exercised. [app/tts/router.py:26](https://github.com/priyamsameer95-sys/THEYA.AUDIO/blob/8369cfc5b641b5c3eb270eea9651a56d02bbc0de/app/tts/router.py#L26), [app/tts/kokoro.py:17](https://github.com/priyamsameer95-sys/THEYA.AUDIO/blob/8369cfc5b641b5c3eb270eea9651a56d02bbc0de/app/tts/kokoro.py#L17).
- Optional two-person dialogue generation has explicit Hugging Face Qwen/Qwen2.5-72B-Instruct, Gemini2.0Flash, Groq llama-3.3-70b-versatile and OpenAI gpt-4o-mini code paths, enabled by corresponding keys. With no configured provider, a deterministic fallback is used. Describe these as provider adapters in source, not four validated live integrations. [app/podcast/dialogue.py:394](https://github.com/priyamsameer95-sys/THEYA.AUDIO/blob/8369cfc5b641b5c3eb270eea9651a56d02bbc0de/app/podcast/dialogue.py#L394).
- Retrieval is implemented as overlapping document chunks persisted to SQLite and hybrid BM25 / TF-IDF cosine / bigram scoring. The code does not establish a vector database or embedding-model deployment. [app/rag/pipeline.py:27](https://github.com/priyamsameer95-sys/THEYA.AUDIO/blob/8369cfc5b641b5c3eb270eea9651a56d02bbc0de/app/rag/pipeline.py#L27), [app/rag/pipeline.py:91](https://github.com/priyamsameer95-sys/THEYA.AUDIO/blob/8369cfc5b641b5c3eb270eea9651a56d02bbc0de/app/rag/pipeline.py#L91).
- Evaluation functions check grounded content terms, query-term coverage and dialogue/banter rules. These are deterministic/heuristic checks, not independently measured factual accuracy. Repository tests exist; no benchmark or model-quality result was rerun for this capture. [app/rag/evals.py:1](https://github.com/priyamsameer95-sys/THEYA.AUDIO/blob/8369cfc5b641b5c3eb270eea9651a56d02bbc0de/app/rag/evals.py#L1), [tests/test_rag_evals.py](https://github.com/priyamsameer95-sys/THEYA.AUDIO/blob/8369cfc5b641b5c3eb270eea9651a56d02bbc0de/tests/test_rag_evals.py#L1).

Suggested substantive line: “A sentence-aware listening workspace: extract a document, retrieve relevant passages, shape a two-voice discussion and route speech synthesis through provider adapters. Grounding and dialogue checks are visible in the implementation.”

## Conversational Voice Screening / hr-screening101

**Strongest original interface:** React campaign dashboard in `hr/original/src/pages/Index.tsx`, campaign detail and candidate queue in `src/pages/CampaignDetail.tsx`, campaign/question setup dialog. Unlike an architecture-only entry, an actual frontend is present.

**Isolated render:** `hr/preview/dist/` after frontend build. Original pages/components remain; only the Supabase adapter and useAuth are replaced with local synthetic campaign/candidate records. The displayed draft campaigns have zero completed calls, avoiding invented screening performance. Writes, live calls and authentication are disabled; CSP blocks external connections. Caption: “Original HR Screening AI frontend — synthetic draft campaigns; no calls placed.”

**Actual implementation evidence:**

- Supabase Edge Functions initiate Twilio calls and receive callback/status/recording events. [supabase/functions/initiate-call/index.ts:90](https://github.com/priyamsameer95-sys/hr-screening101/blob/b57ab2a9fb50e16a3fca194d9ca9b569db829ca7/supabase/functions/initiate-call/index.ts#L90).
- The voice bridge requests a signed ElevenLabs conversation URL, injects campaign/candidate/question context and forwards streamed audio between Twilio and ElevenLabs. It implements queueing, ping/pong and µ-law/PCM sample conversion; these are substantive integration details. [supabase/functions/elevenlabs-stream/index.ts:130](https://github.com/priyamsameer95-sys/hr-screening101/blob/b57ab2a9fb50e16a3fca194d9ca9b569db829ca7/supabase/functions/elevenlabs-stream/index.ts#L130), [index.ts:357](https://github.com/priyamsameer95-sys/hr-screening101/blob/b57ab2a9fb50e16a3fca194d9ca9b569db829ca7/supabase/functions/elevenlabs-stream/index.ts#L357), [index.ts:491](https://github.com/priyamsameer95-sys/hr-screening101/blob/b57ab2a9fb50e16a3fca194d9ca9b569db829ca7/supabase/functions/elevenlabs-stream/index.ts#L491).
- Post-call transcript analysis calls `google/gemini-2.5-flash` through the Lovable AI gateway, using a `save_call_analysis` function/tool schema for notice period, compensation, skills, strengths and recommendation data. [supabase/functions/analyze-response/index.ts:65](https://github.com/priyamsameer95-sys/hr-screening101/blob/b57ab2a9fb50e16a3fca194d9ca9b569db829ca7/supabase/functions/analyze-response/index.ts#L65).
- Important limit: the code maps PROCEED/REJECT/other recommendations directly to QUALIFIED/REJECTED/REVIEW candidate statuses. Do not describe it as human-approved decisioning unless additional evidence is supplied. Stored `confidence` values in this code are constants, not measured accuracy. No live call, hiring-quality evaluation, throughput or business result was validated in this pass. [index.ts:254](https://github.com/priyamsameer95-sys/hr-screening101/blob/b57ab2a9fb50e16a3fca194d9ca9b569db829ca7/supabase/functions/analyze-response/index.ts#L254).
- Frontend uses Vite/React/TypeScript, shadcn/Radix primitives, React Query and Supabase. Lovable tooling in the repository indicates the scaffold/build tool; it does not prove an entire authoring history or named use of other coding assistants. [package.json](https://github.com/priyamsameer95-sys/hr-screening101/blob/b57ab2a9fb50e16a3fca194d9ca9b569db829ca7/package.json#L1).

Suggested substantive line: “A campaign-to-call prototype with an actual screening dashboard: Twilio telephony, an ElevenLabs audio bridge, context-bound prompts and schema-shaped post-call extraction. Live call quality and hiring outcomes remain unverified.”

## Rocket Card Finder

**Strongest original interfaces:** `/cards` from `rocket/original/src/pages/CardListing.tsx` shows real faceted discovery controls; `/card-genius` from `src/pages/CardGenius.tsx` shows the spending-profile form. Prefer these to the marketing homepage, whose savings/user/card-count claims are interface copy without outcome evidence.

**Isolated render:** `rocket/preview/dist/` after frontend build. All original pages/components/styles retained. The financial API/auth adapters return empty local preview datasets; no UAT endpoint, token exchange or savings calculation is contacted. CSP also blocks remote images, so use the original local MoneyControl logo and native form controls rather than relying on unavailable card photos. Caption: “Original credit-card discovery frontend — isolated preview; financial APIs disconnected.”

**Actual implementation evidence:**

- The service module connects init-bundle, card-detail, card-listing, calculation and eligibility requests to a BankKaro UAT partner endpoint. The source establishes API contracts, not current production availability. [src/services/cardService.ts:1](https://github.com/priyamsameer95-sys/rocket-card-finder/blob/a4efcb4b41cf858821c506eceb6527af8da59647/src/services/cardService.ts#L1).
- Listing state includes bank IDs, networks, annual fees, credit-score buckets, category slug, sort choice and an eligibility payload. Client-side safety filtering is visible after the API response. [src/pages/CardListing.tsx:35](https://github.com/priyamsameer95-sys/rocket-card-finder/blob/a4efcb4b41cf858821c506eceb6527af8da59647/src/pages/CardListing.tsx#L35), [CardListing.tsx:120](https://github.com/priyamsameer95-sys/rocket-card-finder/blob/a4efcb4b41cf858821c506eceb6527af8da59647/src/pages/CardListing.tsx#L120).
- SpendingData distinguishes online/offline purchases, food, travel, utilities, insurance and rent; calculation is delegated to the service. Do not invent a recommender formula or model accuracy. [src/services/cardService.ts:5](https://github.com/priyamsameer95-sys/rocket-card-finder/blob/a4efcb4b41cf858821c506eceb6527af8da59647/src/services/cardService.ts#L5).
- No LLM provider/model integration was located in this frontend. The interface contains promotional “AI analyzing” copy; this alone is not evidence of AI decisioning. Treat it as fintech product discovery/API integration, not an established generative-AI product.
- The original frontend is MoneyControl Cards-branded. Its relationship to that organization is not established by the repository and must not be implied as employment/client delivery.

Suggested substantive line: “A spending-led card-discovery interface with bank/network/fee filters, eligibility inputs and comparison controls. The prototype exposes the product journey; rewards and savings results depend on a connected service.”
